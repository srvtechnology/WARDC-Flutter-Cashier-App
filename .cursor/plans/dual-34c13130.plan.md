# Property Listing (Offline-first) with Multipart Uploads

## Decisions

- Upload format: multipart/form-data for images and files.
- Offline cache: Hive. Boxes: `propertyDrafts`, `syncQueue`, `variablesCache`.
- Networking: Dio (reuse configured instance). Auth: Bearer token from `AuthService.getToken()`.

## Files to Create

- `lib/services/property_service.dart` — API: `getAllVariables()`, `savePropertyMultipart(...)` (POST `/property/save`), helpers to build `FormData`.
- `lib/services/sync_service.dart` — background/manual sync of `syncQueue` items; retry with exponential backoff; network check.
- `lib/models/property_models.dart` — minimal DTOs for variables and draft structure; adapters for Hive.
- `lib/controllers/property_controller.dart` — GetX controller managing 5-step wizard state, validation, image picking, draft save/restore, and submit -> queue or direct sync.
- `lib/views/property/property_list_view.dart` — shows drafts and synced items, status badges, add FAB.
- `lib/views/property/property_wizard_view.dart` — stepper UI (5 steps) with required inputs; camera pickers; validation errors; save-as-draft; submit.

## API Contracts

- Variables: POST `/get-all-variable-datas` → cache in Hive with TTL; map to dropdown models.
- Save Property: POST `/property/save` with `Authorization: Bearer <token>`; body built as multipart:
- Text fields (strings/arrays) per steps.
- Registry meters: `registry[0][meter_number]`, `registry[0][meter_image]` files...
- Assessment photos: `assessment_images_1`, `assessment_images_2` files.

## Offline Flow

- On opening wizard: load cached variables from Hive; refresh from server in background.
- During input: autosave draft every change to `propertyDrafts` using `randomdata` id.
- Submit: if offline → enqueue to `syncQueue` with full payload and file paths; if online → attempt immediate upload; on success clear draft; else keep in queue.
- Property list shows: Drafts (local), Pending Sync, Synced (server id available).

## Validation

- Per-step form keys; block navigation forward if invalid.
- Required: categoryType, owner names/contacts, property address, occupancy at least one, registry points, at least 1 meter when provided, assessment core fields.

## Error Handling

- Map Dio errors (timeouts, auth, server). Show `Get.snackbar` and inline messages.
- Token expiration → route to onboarding after clearing.

## Security

- Use HTTPS; token only in header; files read from app sandbox paths; clear drafts on logout (optional confirm).

## Sync

- Manual sync button on list; background trigger on network regained (basic: try on app resume or when list screen opens).
